# Angled type-2 particle world admission

`418CF0` renders the0x50-byte spark/gravel/grass particles. Its original route divided by the center projection's W, discarded finite W<=0 and emitted RHW quads. A geometry shader could not recover a particle already discarded by that CPU step.

For **Angled + FixParticleRendering On + World phase + logical backbuffer + the native640x480 mapping**, the route now constructs XYZ quads. It uses the same combined matrix as the original projection, preserves the front-facing screen-size/clamp calculation, and unprojects the four clip-space corners back into world coordinates. At/behind the center eye it uses the unclamped geometric size rather than dividing by nonpositive W. The existing native fixed-function camera transforms and per-panel GPU correction can then clip each panel independently. No simulation, random generator or per-panel event replay is added.

The quads keep the native diffuse/UV ordering, depth-write/blend settings and512-particle batch cap. Lighting/fog and texture-coordinate generation are set as on the native XYZ billboard route; the particle colour is already shaded. The event's existing saved render-state/texture restoration remains active. Nonfinite world geometry is rejected before submission. An unsupported/singular transform, unknown device/target, nonnative logical mapping, FixParticleRendering Off, Off/Planar, HUD/frontend or offscreen target retains the original RHW path. Defaults and owner settings are unchanged.

`PcD3D9Device::logical_backbuffer_target()` defaults to refusal. The software-state owner implements it from its actual colour target; D3D11 inherits that owner. This query acquires no surface references. A future physical world-source texture must preserve this **logical** identity together with the triple-binding target checks; reflection cubes and other offscreen passes must remain excluded.

The actual `41BD10 -> 418490 -> 418CF0` fixture now passes **650 checks**, using synthetic records, a recording draw boundary and CPU-only target/state objects. It covers old RHW/XYZ billboard contracts, front logical640x480 coordinate/depth/colour/UV parity with and without size clamping, finite front/behind/eye-plane XYZ submission, an emitted behind-center particle inside the actual right-panel frustum,512/600 batch limiting, invalid geometry/singular projection refusal/fallback, and exact offscreen/HUD legacy packets plus saved render-state/refcount/RNG/authored-data restoration. These are packet/matrix assertions, not GPU pixels, visibility, texture orientation, performance or owner acceptance.

The D3D11 RHW path additionally applies the configured UI rectangle; XYZ uses the world/panel viewports. Therefore logical packet-coordinate parity is not a promise of identical old device pixels. The new world coordinates follow the actual particle emitter/camera instead of inheriting HUD layout. Center placement/size under the selected UI-scaling mode is part of the attended comparison.

The first extended fixture used an infinite-far projection that the existing triple-frustum helper deliberately refuses; it now supplies finite native near/far for the side-frustum assertion. The source also explicitly applies the native XYZ lighting/fog/UV states. Logs `work/validation-20261102/particle-world-*` retain both setup and final outcomes. Header consumers and named desktop targets were rebuilt in the serialized CPU-only GO492885 slot, jobs2; focused particle/scene/mission/trace/triples/curve/audit CTest8/8 passes. No game, GPU, audio/input/physical-device initialization, display change or owner install was performed.
