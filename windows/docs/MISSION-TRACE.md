# Bounded native mission trace

For a future coordinated, muted disposable run, set **`OR2_MISSION_TRACE=1` in the owned child environment only**. It is declared in the startup diagnostic inventory. The flag is read once on the first mission-wrapper call; absent,0 or any value other than the exact string1 produces no trace. Restart the disposable process to begin another capture. No game was run for this increment.

The actual native mission wrapper records at most **600 calls** in GAME/mode16, variant6, ready/stage4, type2 or6. Paused and selection-inactive calls remain visible; they can explain a stopped timer. The budget is process-wide across missions and is not a wall-clock timeout. Verify the logged key/sub/type is the intended reported mission. A header announces the budget, and an end line marks exhaustion; no end line can mean the capture ended early. Trace data goes to existing stderr/runtime-log capture; no new path, settings or save writer is added.

Each row snapshots before/after the real mission controller: frame/call number, race key/sub/type, stage/selection, mode/pause/end, player timer/grade/rank, record/participant counts, leading/last racer and first missing PC. It includes current player flags/yaw/course section and at most8 racer records with linked car, active/stopped/activity flags, rank, score, pressure timer and course-position fields. `fractionBits` is the raw IEEE754 float word, so even invalid data stays numeric. Larger/inconsistent racer lists are bounded to available records/eight and explicitly marked `truncated=1`. No names, paths, profile bytes or credentials are logged.

This observes the state handed to the mission controller after traffic work; it does not trace before/after the traffic scheduler or read every linked rival car. A changing timer with a fixed HUD still needs pixel/readout observation. A missing activity bit needs the linked-car/AI path checked.
