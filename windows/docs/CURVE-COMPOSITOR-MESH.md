# Native curve compositor mesh data

`curved_panel_mesh.hpp` consumes the three validated CurvedPanelWarp plans into a renderer-ready, fixed64x36 mesh. Each panel has2,405 packed16-byte XY/UV vertices; all three share one13,824-entry uint16 triangle-list index buffer. The complete output is143,088 bytes, allocation-free, with all three panels published atomically. A refused warp, nonfinite/invalid bounds or out-of-source UV leaves the previous output unchanged.

Destination clip XY is local to each panel viewport, spanning [-1,1]. Source UV stays local to that panel's source image; no texture atlas, array slice, allocation size or window layout is baked into the mesh. The settled math returns lower-left UV, so the packed D3D sampling coordinate is explicitly (sourceU,1-sourceV). No half-texel/pixel-center adjustment is added. Triangle winding is CCW in clip XY, becoming clockwise after the D3D viewport Y flip; a later compositor must select matching raster state. Source addressing/filtering and its restore belong to that consumer.

The grid sizes come directly from the canonical warp constants, not a new quality setting. Only numerical noise up to1e-9 at normalized source edges is clamped; larger out-of-bounds values refuse instead of sampling unrelated source pixels. Virtual Game-FOV render-eye/source-plane changes leave the mesh unchanged because the real measured eye defines UVs. Source projection matrices remain the separate `curved_source_views` output.
